# エージェント/スキル/コマンドの品質監査

Claude Code のエージェント、スキル、コマンドの包括的な品質監査。重み付き基準で各ファイルをスコアリングし、プロダクション準備状況のグレードを付けます。

## 引数

- `[path]` - 監査するディレクトリ（デフォルト: 現在のプロジェクトの `.claude/`）
- `--fix` - 失敗した基準に対する修正提案を生成
- `--verbose` - すべての基準の詳細を表示（失敗のみでなく）

## 使用方法

```bash
/audit-agents-skills              # 現在のプロジェクトを監査
/audit-agents-skills --fix        # 監査 + 修正提案
/audit-agents-skills ~/other-repo # 別のプロジェクトを監査
/audit-agents-skills --verbose    # すべての基準の詳細
```


## フェーズ 1: 発見

**目的**: すべてのエージェント、スキル、コマンドを見つけて分類する

### 手順

1. **ディレクトリをスキャンする**:
   ```
   .claude/agents/
   .claude/skills/
   .claude/commands/
   examples/agents/      (存在する場合)
   examples/skills/      (存在する場合)
   examples/commands/    (存在する場合)
   ```

2. **ファイルを分類する**:
   - **エージェント**: `agents/` ディレクトリ内のファイルで `tools:` フィールドを含む YAML フロントマターがある
   - **スキル**: `skills/` ディレクトリ内のファイル、または `SKILL.md` という名前、またはフロントマターに `allowed-tools:` フィールドがある
   - **コマンド**: `commands/` ディレクトリ内のファイルで `name:` と `description:` を含むフロントマターがある

3. **サマリーを表示する**:
   ```
   Found: X agents, Y skills, Z commands
   ```


## フェーズ 2: 個別ファイルの監査

各ファイルタイプは**重み付き基準**でスコアリングされます。最高スコア:
- **エージェント**: 32 ポイント
- **スキル**: 32 ポイント
- **コマンド**: 20 ポイント

### エージェント（32 ポイント満点）

#### アイデンティティ（重み: 3x）— 12 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| 明確な `name` フィールド | 3 | フロントマター YAML に説明的な `name:` フィールドがある（「agent1」のような汎用名でない） |
| トリガーを含む `description` | 3 | 説明に「when」「use」「trigger」キーワードが含まれ、起動コンテキストを示す |
| `model` の指定 | 3 | フロントマターに `model:` フィールドがある（sonnet/haiku/opus） |
| `tools` が適切に制限されている | 3 | ツールリストに Bash が含まれない（正当化されている場合を除く）、またはリスクのあるツールへの説明がある |

**根拠**: アイデンティティは**発見可能性**と**起動**を決定します。ユーザーがエージェントを見つけたり呼び出したりできなければ、下流の品質は意味がありません。

#### プロンプト品質（重み: 2x）— 8 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| ロールが定義されている | 2 | 「You are」または「Your role」文がありエージェントのペルソナを定義している |
| 出力フォーマットが指定されている | 2 | 「Output」「Format」「Deliverables」という題のセクションがあり期待される構造を指定している |
| スコープ/制限が定義されている | 2 | スコープ、トリガー、またはエージェントを使用すべきでない場合を定義するセクションがある |
| 幻覚防止措置 | 2 | キーワードが含まれている: 「verify」「cite」「source」「evidence」または幻覚に対する警告 |

**根拠**: プロンプト品質はエージェントの応答の**信頼性**と**精度**を決定します。

#### 検証（重み: 1x）— 4 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| 3 つ以上の使用例 | 1 | 少なくとも 3 つの異なる例がある「Examples」「Usage」「Scenarios」セクションがある |
| エッジケースが文書化されている | 1 | 「edge case」「error」「failure」「limitation」シナリオが言及されている |
| 統合が文書化されている | 1 | 一緒に使用する他のエージェント、スキル、ツールが参照されている |
| エラーハンドリングが説明されている | 1 | 「fallback」「recovery」「error handling」または失敗モードが言及されている |

**根拠**: 検証により包括的なテストシナリオを通じた**堅牢性**が確保されます。

#### 設計（重み: 2x）— 8 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| 単一責任 | 2 | ファイルサイズが 5000 トークン未満で、説明が集中している（「汎用」や複数の動詞でない） |
| 重複なし | 2 | 説明が他のエージェントと大幅に重複していない（キーワード類似度 50% 超のチェック） |
| 合成可能（スキル参照） | 2 | 呼び出せるスキルや他のエージェントを参照し、モジュール性を示している |
| 適切なトークン予算 | 2 | ファイルサイズが 8000 トークン未満（コンテキストの肥大化を避ける） |

**根拠**: 設計パターンはエージェントアーキテクチャの**保守性**と**スケーラビリティ**を決定します。


### スキル（32 ポイント満点）

#### 構造（重み: 3x）— 12 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| 有効な SKILL.md またはフロントマター | 3 | ファイルが `SKILL.md` という名前、または `name:` フィールドを含む YAML フロントマターがある |
| `name` が有効 | 3 | 名前が小文字、1〜64 文字、パターン `[a-z0-9-]+` に一致（スペース/特殊文字なし） |
| `description` が空でない | 3 | 説明フィールドが存在し 20 文字超 |
| `allowed-tools` が指定されている | 3 | フロントマターにツールのアクセス権を列挙する `allowed-tools:` フィールドがある |

**根拠**: 構造の準拠により Claude Code ランタイムとの**仕様互換性**が確保されます。

#### コンテンツ（重み: 2x）— 8 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| 方法論/ワークフローが説明されている | 2 | 「Methodology」「Workflow」「Process」という題のセクション、または番号付きステップがある |
| 出力フォーマットが指定されている | 2 | 成果物フォーマット（Markdown、JSON、レポート構造）を指定するセクションがある |
| 例が提供されている | 2 | 具体的なインスタンスがある「Examples」「Usage」「Scenarios」セクションがある |
| チェックリストが含まれている | 2 | Markdown チェックボックス構文 `- [ ]` または `- [x]` がアクションアイテムとして含まれている |

**根拠**: コンテンツの豊富さは**使いやすさ**と**学習曲線**を決定します。

#### 技術（重み: 1x）— 4 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| スクリプトにエラーハンドリングがある | 1 | バンドルされたスクリプトが存在する場合、`set -e`、`trap`、または `|| exit` パターンが含まれている |
| ハードコードされたパスがない | 1 | コードや指示に `/Users/`、`/home/`、`C:\` のような絶対パスがない |
| シークレットがない | 1 | 「password」「secret」「token」「api_key」「credentials」のようなキーワードが平文でない |
| 依存関係が文書化されている | 1 | 外部ツールが必要な場合、「Requirements」「Dependencies」「Prerequisites」セクションがある |

**根拠**: 技術的な衛生状態は**移植性の問題**と**セキュリティリスク**を防ぎます。

#### 設計（重み: 2x）— 8 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| 単一責任 | 2 | 説明が一つのドメインに集中している（「general」や多目的でない） |
| 明確なトリガー | 2 | 「When to use」「Triggers」「Activation criteria」を定義するセクションがある |
| 他のスキルと重複なし | 2 | 説明がプロジェクト内の他のスキルのキーワードを 50% 超重複させていない |
| 移植可能 | 2 | 移植性を損なう Claude Code 固有の拡張がない（カスタム API を確認） |

**根拠**: 設計はプロジェクト間での**発見可能性**と**保守性**を決定します。


### コマンド（20 ポイント満点）

#### 構造（重み: 3x）— 12 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| 有効なフロントマター | 3 | `name:` と `description:` フィールドの両方を含む YAML フロントマターがある |
| 引数を取る場合の `argument-hint` | 3 | 本文で `$ARGUMENTS` 変数が使用されている場合、フロントマターに `argument-hint:` フィールドがある |
| ステップバイステップのワークフロー | 3 | 本文に番号付きセクション（1.、2.、3.）または明確なフェーズ構造がある |
| 使用例 | 3 | 「Usage」「Examples」という題のセクション、または呼び出しパターンが示されている |

**根拠**: 構造はコマンドユーザーの**使いやすさ**と**学習容易性**を決定します。

#### 品質（重み: 2x）— 8 ポイント

| 基準 | ポイント | 検出方法 |
|-----------|--------|-----------|
| エラーハンドリング | 2 | 「error」「failure」「fallback」、または失敗に対する条件パスが言及されている |
| 出力フォーマットが定義されている | 2 | コマンドが何を出力するか（レポート、ファイル、サマリー）とその構造を指定している |
| バリデーションゲート | 2 | チェックポイント、検証ステップ、または「before proceeding」チェックが含まれている |
| 引数が適切に解析されている | 2 | 引数を取る場合、`$ARGUMENTS` の解析/バリデーション方法を示している（デフォルト値、バリデーション） |

**根拠**: 品質は**信頼性**と**プロダクション準備状況**を決定します。


## フェーズ 3: スコアリング

### 個別ファイルのスコア

```
Score = (Points Obtained / Max Points) × 100
```

**例**: エージェントが 26/32 ポイント → 81% スコア

### グレード割り当て

| グレード | スコア範囲 | ステータス |
|-------|-------------|--------|
| A | 90-100% | プロダクション準備完了 ✅ |
| B | 80-89% | 良好（プロダクション閾値） ⚠️ |
| C | 70-79% | 改善が必要 🔧 |
| D | 60-69% | 重大なギャップ ⚠️ |
| F | <60% | クリティカルな問題 ❌ |

**プロダクション閾値**: 80%（グレード B 以上）

### プロジェクト全体のスコア

ファイルタイプによる加重平均:
```
Overall = (Σ Agent Scores × Agent Count + Σ Skill Scores × Skill Count + Σ Command Scores × Command Count) / Total Files
```

## 業界コンテキスト

**出典**: LangChain エージェントレポート 2026（確認済み）

**主要統計**:

## 実装メモ

### 検出パターン

**フロントマターの解析**:
```python
import re
yaml_match = re.search(r'^---\n(.*?)\n---', content, re.DOTALL)
if yaml_match:
    import yaml
    frontmatter = yaml.safe_load(yaml_match.group(1))
```

**キーワード検出**（大文字小文字を区別しない）:
```python
has_trigger = any(word in description.lower() for word in ['when', 'use', 'trigger'])
```

**トークンカウント**（概算）:
```python
tokens = len(content.split()) * 1.3  # 大まかな見積もり: 1 トークン ≈ 0.75 単語
```

### 重複検出

Jaccard 類似度を使って説明を比較する:
```python
def jaccard_similarity(desc1, desc2):
    words1 = set(desc1.lower().split())
    words2 = set(desc2.lower().split())
    intersection = words1 & words2
    union = words1 | words2
    return len(intersection) / len(union) if union else 0

# 類似度 > 0.5（50% キーワード重複）の場合はフラグを立てる
```

### グレードのカラーコーディング（ターミナル出力）
