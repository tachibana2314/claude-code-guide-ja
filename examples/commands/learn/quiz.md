# クイズ

最近書いたまたは承認したコードの理解度をテストします。

## 使用法

```
/learn:quiz                     # 最後に作業したコードのクイズ
/learn:quiz error handling      # 特定の側面にフォーカス
/learn:quiz --hard              # より難しい問題
```

## 手順

1. 最後に作業したコードを特定（書いた、編集した、または AI から承認した）
2. 異なるレベルで理解度をテストする3-5問の質問を生成:
   - **想起**: このコードは何をするか？
   - **理解**: なぜこのアプローチが選ばれたか？
   - **応用**: X が変わったら何が起きるか？
   - **分析**: このアプローチのトレードオフは何か？
   - **統合**: これをどのように拡張するか？
3. 問題を1つずつ提示する
4. 正しい回答を明かす前に私の答えを待つ
5. 「正解/不正解」だけでなく、各回答とともに説明を提供する

## 問題タイプ

### レベル 1: 想起
- 「関数 X は何を返すか？」
- 「Y はどのようなパラメーターを受け取るか？」
- 「Z が呼ばれると何が起きるか？」

### レベル 2: 理解
- 「ここで Y ではなく X を使うのはなぜか？」
- 「このパターンはどんな問題を解決するか？」
- 「この行はなぜ必要か？」

### レベル 3: 応用
- 「行 X を削除したら何が起きるか？」
- 「このコードに機能 Y を追加するにはどうするか？」
- 「入力 Z が提供されたら何が壊れるか？」

### レベル 4: 分析
- 「このアプローチのパフォーマンスへの影響は？」
- 「どのようなエッジケースが問題を引き起こす可能性があるか？」
- 「これは代替 X とどう比較されるか？」

### レベル 5: 統合
- 「テスト容易性を高めるためにこれをどのようにリファクタリングするか？」
- 「X をサポートするには何を変更する必要があるか？」
- 「Y を追加する拡張機能を設計してください」

## フォーカスエリア

フォーカスが指定されている場合（例: `/learn:quiz error handling`）、次の質問を優先します:

| フォーカス | 質問のテーマ |
|-------|-----------------|
| `error handling` | try/catch、エラータイプ、リカバリ戦略 |
| `performance` | Big-O、最適化、ボトルネック |
| `security` | 入力バリデーション、XSS、インジェクション |
| `testing` | テストケース、エッジケース、モッキング |
| `architecture` | パターン、関心の分離、SOLID |
| `types` | TypeScript 型、型推論、ジェネリクス |

## 難易度モード

### デフォルト
- 3問
- レベル 1-3 の混合
- 現在のコードの理解に焦点

### `--hard`
- 5問
- レベル 3-5
- 仮想的な変更を含む
- トレードオフと代替案について問う

## レスポンスフォーマット

各質問について:

```
## Question 1 of 3

[質問文]

What's your answer?

---
（ユーザーが回答した後）

### Feedback

[正解かどうかとその理由]

**Key insight**: [これがテストするコンセプト]

**Related concept**: [さらに探求する内容]

Ready for the next question?
```

## クイズ完了後

以下を要約します:
- スコア: X/Y 正解
- 強み: [よく理解できているトピック]
- 復習が必要: [再確認すべきトピック]
- 推奨される練習: [具体的な練習問題]

## セッション例

```
User: /learn:quiz

Claude: あなたの最後のコード — データフェッチのための useEffect フックを見ています。

## Question 1 of 3

useEffect に空の依存配列 [] があります。
これはエフェクトが実行されるタイミングについて何を意味しますか？

User: コンポーネントがマウントされた時にのみ一度実行される

Claude: ### Feedback
正解！空の依存配列はエフェクトがマウント時にのみ実行されることを意味します
（アンマウント時にクリーンアップも実行）。

**Key insight**: 依存配列はエフェクトがいつ再実行されるかを制御します。

**Related concept**: 配列なしの場合と [someValue] の場合に何が起きるか？

Ready for Question 2?
```

## ユーザーへのヒント

1. **正直に** — 間違った答えは学習の機会
2. **推論を説明する** — 正しい答えでもギャップを特定するのに役立つ
3. **フォローアップを求める** — フィードバックが不明確なら深く掘り下げる
4. **弱点を追跡** — より練習が必要なトピックをメモする
