# テスト規約

## 構造
- AAA パターン（Arrange-Act-Assert）を使用
- describe ブロックで機能単位にグループ化
- it/test の説明は具体的に（「正しく動作する」は避ける）

## 命名
- テストファイル: `[対象ファイル名].test.ts`
- describe: 対象の関数名またはコンポーネント名
- it/test: 「〜の場合、〜を返す/する」形式

## モック
- 外部APIのみモック。内部関数はモックしない
- モックはテストファイル内で定義（共有モックファイル禁止）
- `jest.mock()` よりも依存性注入を優先

## カバレッジ
- 新規コード: 80%以上のカバレッジ必須
- 重要なビジネスロジック: 100%カバレッジ推奨
- UIコンポーネント: スナップショット + インタラクションテスト

## アンチパターン（避けること）
- テスト内での複数のアサーション（1テスト1アサーション推奨）
- 実装の詳細のテスト（振る舞いをテストする）
- テスト間の依存関係
- ハードコードされた日付/時間
