# 既知の問題とクリティカルなバグ

このドキュメントは、コミュニティレポートと公式コミュニケーションに基づいて、Claude Codeユーザーに影響を与えることが確認されたクリティカルな問題を追跡します。

> **最終更新**: 2026年1月28日
> **ソース**: [GitHub Issues](https://github.com/anthropics/claude-code/issues) + [Anthropic公式コミュニケーション](https://www.anthropic.com/engineering)

## 🚨 アクティブなクリティカル問題

### 1. GitHubイシューが誤ったリポジトリに自動作成される（2025年12月〜現在）

**深刻度**: 🔴 **クリティカル - セキュリティ/プライバシーリスク**
**ステータス**: ⚠️ アクティブ（2026年1月28日時点）
**イシュー**: [#13797](https://github.com/anthropics/claude-code/issues/13797)
**最初の報告**: 2025年12月12日
**影響バージョン**: v2.0.65以降

#### 問題

Claude Codeは、ローカルのgitリポジトリディレクトリ内で作業していても、ユーザーのプライベートリポジトリではなく**パブリックな `anthropics/claude-code` リポジトリにGitHubイシューを体系的に作成します**。

#### 影響

**高 - プライバシー/セキュリティ**: 少なくとも **17件以上の確認されたケース**で、ユーザーが誤って公開リポジトリに機密情報を公開:

- データベーススキーマ
- APIクレデンシャルと設定の詳細
- インフラアーキテクチャ
- プライベートプロジェクトのロードマップ
- セキュリティ設定

#### 症状

- 予期しない `--repo anthropics/claude-code` フラグでイシューが作成される
- プライベートプロジェクトの詳細がパブリックなanthropics/claude-codeイシューに表示される
- パブリックリポジトリへのイシュー作成前に確認プロンプトがない
- ローカルのgitリポジトリで「イシューを作成して」と依頼した際に発生

#### 誤って作成された例

最近確認されたケース（2026年1月）:
- [#20792](https://github.com/anthropics/claude-code/issues/20792): 「削除済み - 誤ったリポジトリに作成」
- [#16483](https://github.com/anthropics/claude-code/issues/16483), [#16476](https://github.com/anthropics/claude-code/issues/16476): 「ClaudeがWRONG REPOにISSUEをOPENしている」
- [#17899](https://github.com/anthropics/claude-code/issues/17899): 「Claude Codeが突然claude codeリポジトリにイシューを作成し始めた」
- [#16464](https://github.com/anthropics/claude-code/issues/16464): 「[誤った投稿] 削除してください」

完全なリスト: [「wrong repo」または「delete this」で検索](https://github.com/anthropics/claude-code/issues?q=is%3Aissue+%22wrong+repo%22+OR+%22delete+this%22)

#### 根本原因（仮説）

Claude Codeが以下を混同している可能性:
- **Claude Code自体についての正当なフィードバック** → `anthropics/claude-code`（正しい）
- **ユーザープロジェクトのイシュー** → 現在のリポジトリ（デフォルトであるべき）

ツールが `anthropics/claude-code` をデフォルトターゲットとしてハードコードまたは過度に優先している可能性があります。

#### 回避策

**🛡️ Claude Codeを通じてGitHubイシューを作成する前に:**

1. **ターゲットリポジトリを常に確認する**:
   ```bash
   # 現在のリポジトリを確認
   git remote -v
   ```

2. **リポジトリを明示的に指定する**:
   ```bash
   gh issue create --repo YOUR_USERNAME/YOUR_REPO --title "..." --body "..."
   ```

3. **実行前にコマンドをレビューする**:
   - `--repo anthropics/claude-code` フラグを確認する
   - 存在して不正確な場合は中止して正しいリポジトリを指定する

4. **すべての `gh` コマンドに手動承認を使用する** (Claude設定で)

5. **バグが修正されるまでイシュー作成プロンプトに機密情報を含めない**

#### 影響を受けた場合

機密情報を公開するイシューを誤って作成した場合:

1. **直ちにGitHubサポートに連絡して**イシューの削除をリクエストする（閉じるだけでなく）
2. **公開されたクレデンシャルをローテーションする**（APIキー、パスワード、トークン）
3. **Anthropicに報告する** [セキュリティメール](mailto:security@anthropic.com)（セキュリティに敏感な情報の場合）
4. **データ漏洩を確認する**: 公開された情報の使用状況を監視する

#### 公式対応

2026年1月28日時点: **イシューはオープンのまま**、公式修正は発表されていない。

**追跡**: [イシュー #13797](https://github.com/anthropics/claude-code/issues/13797) (2025年12月12日からオープン)

### 2. 過剰なトークン消費（2026年1月〜現在）

**深刻度**: 🟠 **高 - コストへの影響**
**ステータス**: ⚠️ 報告済み（Anthropicが調査中）
**イシュー**: [#16856](https://github.com/anthropics/claude-code/issues/16856)
**最初の報告**: 2026年1月8日
**影響バージョン**: v2.1.1以降（報告）、それ以前のバージョンにも影響する可能性あり

#### 問題

複数のユーザーが以前のバージョンと比較して**4倍以上速いトークン消費**を報告しており、以下を引き起こしています:
- レートリミットへの到達が通常より大幅に速い
- 同じワークフローで大幅に多くのトークンを消費
- 予期しないコスト増加

#### 症状

イシュー #16856 より:
> 「今日の朝からCC 2.1.1にアップデートして以来、使用量が馬鹿げています。同じプロジェクトで数ヶ月間、同じルーティン、同じ時間。でも今日は5時間制限に4倍以上速く達しています！」

一般的な報告:
- 週次制限が1〜2日で消耗（通常5〜7日）
- 2〜3つのメッセージの後にセッションが90%のコンテキストに達する
- 同一操作で4〜20倍のトークン消費

#### 背景

**休日使用量ボーナスの終了**: 2025年12月25〜31日、Anthropicは休日ギフトとして使用量制限を2倍にしました。2026年1月1日に制限が通常に戻ったとき、ユーザーは「容量の低下」を体験しました。

ただし、**このタイミングを超えても報告が続いており**、潜在的な根本的問題を示唆しています。

#### Anthropicの対応

[The Register](https://www.theregister.com/2026/01/05/claude_devs_usage_limits/) より（2026年1月5日）:
> 「Anthropicは『このような報告をすべて真剣に受け止めているが、トークン使用量に関連する欠陥は特定していない』と述べ、推論スタックのバグを除外したことを示した。」

**ステータス**: Anthropicによって2026年1月28日時点で**公式にはバグとして確認されていない**。

#### 関連イシュー

20件以上の報告（2025年12月〜2026年1月）:
- [#17687](https://github.com/anthropics/claude-code/issues/17687): 「2026年1月以降のトークン消費率の予期せぬ上昇」
- [#16073](https://github.com/anthropics/claude-code/issues/16073): 「[クリティカル] Claude Codeの品質低下 - 指示を無視、過剰なトークン使用」
- [#17252](https://github.com/anthropics/claude-code/issues/17252): 「セッション使用量追跡での過剰なトークン消費率」
- [#13536](https://github.com/anthropics/claude-code/issues/13536): 「新しいセッション初期化での過剰なトークン使用量」

[完全な検索](https://github.com/anthropics/claude-code/issues?q=is%3Aissue+excessive+token+created%3A2025-12-01..2026-01-28)

#### 回避策

Anthropicが調査中の間:

1. **トークン使用量を積極的に監視する**:
   ```
   /context
   ```
   定期的に使用トークン数と容量を確認する

2. **短いセッションを使用する**:
   - コンテキストが50〜60%に近づいたらセッションを再起動する
   - 複雑なタスクを複数のセッションに分割する

3. **auto-compactを無効にする**（効果がある場合）:
   ```bash
   claude config set autoCompaction false
   ```

4. **MCPツールを減らす**（必要でない場合）:
   - `~/.claude.json`（フィールド `"mcpServers"`）をレビューする
   - 未使用のサーバーを無効にする

5. **サブエージェントを使用する**（独立したタスクに）:
   - サブエージェントは別々のコンテキストウィンドウを持つ
   - 複雑な操作にはTaskツールを使用する

6. **使用パターンを追跡する**:
   - バージョンアップグレード前後を比較する
   - 異常なスパイクをドキュメント化する

#### 調査のヒント

過剰な消費が発生している場合:

1. **Claude Codeのバージョンを確認する**: `claude --version`
2. **バージョンを比較する**: 利用可能であれば以前の安定バージョンでテストする
3. **パターンをドキュメント化する**: どの操作が高い使用量をトリガーするか？
4. **データを含めて報告する**: イシューレポートにバージョン、操作タイプ、トークン数を含める

## ✅ 解決済みの過去の問題

### モデル品質の低下（2025年8〜9月）

**深刻度**: 🔴 **クリティカル**
**ステータス**: ✅ **解決済み**（2025年9月中旬）
**タイムライン**: 2025年8月25日〜9月初旬

#### 問題

ユーザーがClaude Codeの以下を報告:
- 以前のバージョンより悪い出力
- 予期しない構文エラー
- 予期しない文字の挿入（英語のレスポンスにタイ語/中国語テキスト）
- 基本タスクの失敗
- 不正確なコード編集

#### 根本原因

Anthropicは**3つのインフラバグ**を特定（モデルの劣化ではない）:

1. **トラフィックの誤ルーティング**: Claude Codeリクエストの約30%が間違ったサーバータイプにルーティングされ、レスポンスが低下
2. **出力の破損**: 8月25日に展開された設定ミスによりトークン生成エラーが発生
3. **XLA:TPUのミスコンパイル**: パフォーマンス最適化によってトークン選択に影響する潜在的なコンパイラバグが引き起こされた

#### コミュニティへの影響

- **大規模なキャンセルキャンペーン**（2025年8〜9月）
- コミュニティの理論: コスト削減のための意図的なモデル低下（量子化）
- Redditのセンチメントが急落

#### Anthropicの対応

**公式ポストモーテム**: [3つの最近の問題のポストモーテム](https://www.anthropic.com/engineering/a-postmortem-of-three-recent-issues)（2025年9月17日）

重要な引用:
> 「私たちは需要、時間帯、サーバー負荷によってモデルの品質を低下させることは決してありません。ユーザーが報告した問題はインフラのバグのみによるものでした。」

**解決策**: すべてのバグが2025年9月中旬までに修正されました。

## 🔄 LLMの日々のパフォーマンス変動

**タイプ**: 期待される動作（バグではない）
**深刻度**: 🟡 **低 - 認識**
**ステータス**: LLM推論に固有、特定のバージョンに限定されない

### これは何か

Claudeの出力品質は、同一のプロンプトとクリーンなコンテキストウィンドウでも、セッションごとに著しく変動する場合があります。これはコンテキストウィンドウの劣化（セッション内でコンテキストが蓄積するにつれて起こる）とは異なります。これは新鮮なセッション間の変動についてのものです。

ユーザーは、前日うまく機能していたタスクで、より短いレスポンス、より保守的な提案、または予期しない拒否を報告することがあります。これはモデルのダウングレードのように感じるかもしれませんが、そうではありません。

### 根本原因

**確率的推論**: 温度が0より高いということは、すべての推論実行が非決定論的であることを意味します。同じプロンプトを2回実行すると、異なるトークンシーケンスが生成されます。これは言語モデルの機能の根本的な部分です。

**MoEルーティングの変動**: Claudeはミクスチャーオブエキスパートアーキテクチャを使用しています。各フォワードパスで、ルーティングメカニズムがどのエキスパートの重みを活性化するかを選択します。異なる実行では異なる組み合わせが活性化され、意味的に同一の入力でも異なる出力が生成されます。

**インフラの変動**: 本番環境では、リクエストは負荷レベル、ハードウェアの世代、熱状態が異なる様々なサーバーに到達します。これらの要素が推論中の浮動小数点演算の数値精度に影響し、微妙ではあるが実際の出力差異を生み出します。

**コンテキストの感度**: `/clear` を使っても、セッション間の小さな違いが蓄積します。システムプロンプト、ツールリスト、セッション初期化のすべてがモデルの最初の出力に微妙に影響します。

### 観察できるシグナル

| シグナル | 見えるもの | 意味するもの |
|---------|-----------|------------|
| レスポンスの長さ | 通常より短く、詳細が少ない | ルーティングがより保守的なパスに到達した |
| 拒否 | 通常機能するエッジケースが拒否される | このランドでの安全キャリブレーションが異なる |
| コードスタイル | 予想より冗長またはより最小限 | エキスパートミックスの活性化が異なった |
| 創造性 | より保守的で、より革新的でない提案 | 能力の損失ではなく、サンプリングの結果 |
| 冗長性 | 通常より多くの注意書きと免責事項 | トークン確率の通常の変動 |

### これではないもの

- **モデルのダウングレードではない**: Anthropicはモデルを意図的にバージョン管理し、変更を文書化します。日々の変動は同じモデルバージョン内で起こります。
- **報告すべきバグではない**: この動作はLLM文献で期待され文書化されています。確率的推論に固有です。
- **永続的ではない**: 次のセッションはおそらく異なる動作をします。「悪い」実行は持続的な変化を示しません。
- **コンテキストウィンドウの劣化ではない**: それはトークンの蓄積によって引き起こされるセッション内の現象です。これは新鮮なスタートでのセッション間の変動です。

> 2025年8〜9月のインシデント（[上記の解決済み問題を参照](#モデル品質の低下2025年89月)）は例外でした: Anthropicは体系的な劣化を引き起こす実際のインフラバグを確認しました。真の体系的な劣化はまれであり、Anthropicはそれを調査します。通常のセッション間変動は別のものです。

### 軽減策

**プロンプトを制約する**: より具体的なプロンプトは出力空間を減らし、変動をあまり目立たせません。「X、Y、Zを行い、型Tを返し、エッジケースEを処理する関数を書いてください」は「Xを処理するものを書いてください」より一貫した出力を生み出します。

**重要な作業の前に新鮮なコンテキスト**: 重要なタスクの前に `/clear` を実行します。以前の探索的な作業からの蓄積されたセッションノイズは、同じセッション内であっても後続の出力を歪める可能性があります。

**再定式化して再試行**: 出力が期待と異なる場合、異なる表現で同じリクエストを試みます。2番目の定式化は異なるエキスパートパスを経由することが多く、より良い結果を生み出します。

**既知の良好なプロンプトと比較する**: 以前のセッションで優れた出力を生み出したプロンプトがあれば、参照として使用します。今日のそのプロンプトのバージョンが一貫して目に見えて悪い出力を生み出す場合、それは詳細な調査に値します（再現可能であればGitHubイシューの可能性）。

**タスクタイプ別に期待を調整する**: 決定論的タスク（正規表現、単純な変換、明確に定義されたアルゴリズム）は、創造的またはジャッジメントが重いタスクより変動が少ない傾向にあります。高い信頼性で前者にClaude Codeを使用し、後者についてはワークフローにレビューステップを組み込みます。
