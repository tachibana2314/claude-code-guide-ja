# データプライバシーと保持ガイド

> **重要**: Claude Codeと共有するものはすべてAnthropicのサーバーに送信される。このガイドでは、どのデータがマシンから離れるのか、そして機密情報を保護する方法を説明する。

## TL;DR - 保持サマリー

| 設定 | 保持期間 | 学習用途 | 有効化方法 |
|---------------|------------------|----------|---------------|
| **コンシューマー（デフォルト）** | 5年 | あり | （デフォルト状態） |
| **コンシューマー（オプトアウト）** | 30日 | なし | [claude.ai/settings](https://claude.ai/settings/data-privacy-controls) |
| **Team / Enterprise / API** | 30日 | なし（デフォルト） | Team、Enterpriseプラン、またはAPIキーを使用 |
| **ZDR（ゼロデータ保持）** | サーバー側0日 | なし | 適切に設定されたAPIキー |

**即座に取るべき行動**: [トレーニングデータ使用を無効化](https://claude.ai/settings/data-privacy-controls)して、保持期間を5年から30日に削減する。


## 1. データフローの理解

### マシンから離れるもの

Claude Codeを使用すると、以下のデータがAnthropicに送信される:

```
┌─────────────────────────────────────────────────────────────┐
│                    あなたのローカルマシン                    │
├─────────────────────────────────────────────────────────────┤
│  • 入力したプロンプト                                        │
│  • Claudeが読み込むファイル（除外されていなければ.envも含む!）│
│  • MCPサーバーの結果（SQLクエリ、APIレスポンス）             │
│  • Bashコマンドの出力                                        │
│  • エラーメッセージとスタックトレース                        │
└───────────┬──────────────────┬──────────────┬───────────────┘
            │                  │              │
            ▼ HTTPS/TLS       ▼ HTTPS        ▼ HTTPS
┌───────────────────┐ ┌──────────────┐ ┌─────────────────────┐
│   ANTHROPIC API   │ │   STATSIG    │ │       SENTRY        │
├───────────────────┤ ├──────────────┤ ├─────────────────────┤
│ • あなたのプロンプト│ │ • レイテンシー│ │ • エラーログ        │
│ • モデルレスポンス  │ │   信頼性     │ │ • コードや          │
│ • あなたのティアに  │ │ • コードや   │ │   ファイルパスなし  │
│   基づく保持       │ │  ファイルパス│ │                     │
│                   │ │   なし       │ │                     │
└───────────────────┘ └──────────────┘ └─────────────────────┘
                       (オプトアウト:    (オプトアウト:
                       DISABLE_         DISABLE_ERROR_
                       TELEMETRY=1)     REPORTING=1)
```

### 実際の意味

| シナリオ | Anthropicに送信されるデータ |
|----------|------------------------|
| `src/app.ts`を読むようClaudeに依頼する | ファイルの完全な内容 |
| Claude経由で`git status`を実行する | コマンドの出力 |
| MCPが`SELECT * FROM users`を実行する | ユーザーデータを含むクエリ結果 |
| Claudeが`.env`ファイルを読む | APIキー、パスワード、機密情報 |
| コードでエラーが発生する | パスを含む完全なスタックトレース |


## 2. Anthropicの保持ポリシー

### ティア1: コンシューマーデフォルト（トレーニング有効）

- **保持期間**: 5年
- **用途**: モデル改善、トレーニングデータ
- **適用対象**: トレーニング設定ONのFree、Pro、Maxプラン

### ティア2: コンシューマーオプトアウト（トレーニング無効）

- **保持期間**: 30日
- **用途**: セーフティ監視、不正使用防止のみ
- **有効化方法**:
  1. https://claude.ai/settings/data-privacy-controls にアクセス
  2. 「会話でのモデルトレーニングを許可する」を無効化
  3. 変更は即座に適用される

### ティア3: コマーシャル（Team / Enterprise / API）

- **保持期間**: 30日
- **用途**: セーフティ監視、不正使用防止のみ
- **トレーニング**: デフォルトではトレーニングに使用されない（オプトアウト不要）
- **適用対象**: Teamプラン、Enterpriseプラン、APIユーザー、サードパーティプラットフォーム、Claude Gov

### ティア4: ゼロデータ保持（ZDR）

- **保持期間**: サーバー側0日（ローカルクライアントキャッシュは最大30日間持続する可能性がある）
- **用途**: Anthropicサーバー上には何も保持されない
- **要件**: 適切に設定されたAPIキー（[Anthropicドキュメント](https://www.anthropic.com/enterprise)参照）
- **ユースケース**: HIPAA（別途BAAが必要）、GDPR、PCI-DSS準拠、政府契約

> **重要**: データはTLS経由で転送中は暗号化されるが、Anthropicのサーバー上では**保存時に暗号化されない**。セキュリティ評価にこの点を考慮すること。


## 3. 既知のリスク

### リスク1: 自動ファイル読み込み

Claude Codeはコンテキストを理解するためにファイルを読み込む。デフォルトでは以下が含まれる:

- `.env`と`.env.local`ファイル（APIキー、パスワード）
- `credentials.json`、`secrets.yaml`（サービスアカウント）
- ワークスペーススコープ内のSSHキー
- データベース接続文字列

**対策**: `excludePatterns`を設定する（セクション4参照）。

### リスク2: MCPデータベースアクセス

データベースMCPサーバー（Neon、Supabase、PlanetScale）を設定した場合:

```
あなたのクエリ: 「最近の注文を見せて」
            ↓
MCPが実行: SELECT * FROM orders LIMIT 100
            ↓
送信される結果: 顧客名、メール、住所を含む100行
            ↓
Anthropicに保存: あなたの保持ティアに従って
```

**対策**: 本番データベースに絶対に接続しない。匿名化されたデータを持つ開発/ステージング環境を使用する。

### リスク3: シェルコマンドの出力

Bashコマンドとその出力がコンテキストに含まれる:

```bash
# この出力はAnthropicに送信される:
$ env | grep API
OPENAI_API_KEY=sk-abc123...
STRIPE_SECRET_KEY=sk_live_...
```

**対策**: フックを使用して機密なコマンド出力をフィルタリングする。

### リスク4: `/bug`コマンドがすべてを送信する（5年間保持）

Claude Codeで`/bug`を実行すると、**完全な会話履歴**（すべてのコード、ファイルの内容、潜在的に機密情報を含む）がバグのトリアージのためにAnthropicに送信される。このデータはトレーニングオプトアウト設定に関係なく、**5年間**保持される。

これはあなたのプライバシー設定から独立している: トレーニングを無効化して30日間の保持にしていても、バグレポートは独自の5年間の保持ポリシーに従う。

**対策**: 機密コードベースで作業する場合は、コマンドを完全に無効化する:

```bash
export DISABLE_BUG_COMMAND=1
```

または、シェルプロファイル（`~/.zshrc`、`~/.bashrc`）に追加して永続化する。

### リスク5: 記録されたコミュニティのインシデント

| インシデント | 出典 |
|----------|--------|
| Claudeがデフォルトで`.env`を読む | r/ClaudeAI、GitHubのissue |
| 不十分に設定されたMCPでのDROP TABLEの試み | r/ClaudeAI |
| 環境変数経由で露出した認証情報 | GitHubのissue |
| 悪意あるMCPサーバー経由のプロンプトインジェクション | r/programming |


## 4. 保護措置

### 即座に取るべきアクション

#### 4.1 トレーニングをオプトアウトする

1. https://claude.ai/settings/data-privacy-controls にアクセス
2. 「モデルトレーニングを許可する」をOFFに切り替え
3. 保持期間が5年から30日に削減される

#### 4.2 ファイル除外を設定する

`.claude/settings.json`で`permissions.deny`を使用して機密ファイルへのアクセスをブロックする:

```json
{
  "permissions": {
    "deny": [
      "Read(./.env*)",
      "Edit(./.env*)",
      "Write(./.env*)",
      "Bash(cat .env*)",
      "Bash(head .env*)",
      "Read(./secrets/**)",
      "Read(./**/credentials*)",
      "Read(./**/*.pem)",
      "Read(./**/*.key)",
      "Read(./**/service-account*.json)"
    ]
  }
}
```

> **注**: 旧来の`excludePatterns`と`ignorePatterns`設定は2025年10月に廃止された。代わりに`permissions.deny`を使用すること。

> **警告**: `permissions.deny`には[既知の制限事項](./security-hardening.md#known-limitations-of-permissionsdeny)がある。多層防御のために、セキュリティフックと外部の機密情報管理と組み合わせること。

#### 4.3 セキュリティフックを使用する

`.claude/hooks/PreToolUse.sh`を作成する:

```bash
#!/bin/bash
INPUT=$(cat)
TOOL_NAME=$(echo "$INPUT" | jq -r '.tool.name')

if [[ "$TOOL_NAME" == "Read" ]]; then
    FILE_PATH=$(echo "$INPUT" | jq -r '.tool.input.file_path')

    # 機密ファイルの読み込みをブロック
    if [[ "$FILE_PATH" =~ \.env|credentials|secrets|\.pem|\.key ]]; then
        echo "ブロック: 機密ファイルの読み込みを試みました: $FILE_PATH" >&2
        exit 2  # 操作をブロック
    fi
fi
```

#### 4.4 テレメトリーとエラーレポートをオプトアウトする

Claude Codeは運用メトリクス（Statsig）とエラーログ（Sentry）のためにサードパーティサービスに接続する。これらにはあなたのコードやファイルパスは含まれないが、完全に無効化することができる:

| 変数 | 無効化される内容 |
|----------|-----------------|
| `DISABLE_TELEMETRY=1` | Statsigの運用メトリクス（レイテンシー、信頼性、使用パターン） |
| `DISABLE_ERROR_REPORTING=1` | Sentryのエラーログ |
| `DISABLE_BUG_COMMAND=1` | `/bug`コマンド（完全な会話履歴の送信を防ぐ） |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` | すべての非必須ネットワークトラフィックを一度に |
| `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1` | セッション品質調査（注: 調査は数値評価のみを送信し、トランスクリプトは送信しない） |

永続的な効果のためにシェルプロファイルに追加する:

```bash
# ~/.zshrcまたは~/.bashrcに
export DISABLE_TELEMETRY=1
export DISABLE_ERROR_REPORTING=1
export DISABLE_BUG_COMMAND=1
```

> **注**: Bedrock、Vertex、またはFoundryプロバイダーを使用する場合、すべての非必須トラフィック（テレメトリー、エラーレポート、bugコマンド、調査）はデフォルトで無効化される。

### MCPのベストプラクティス

| ルール | 理由 |
|------|-----------|
| **本番データベースに絶対に接続しない** | すべてのクエリ結果がAnthropicに送信される |
| **読み取り専用のデータベースユーザーを使用する** | DROP/DELETE/UPDATEの事故を防ぐ |
| **開発データを匿名化する** | PIIの露出リスクを削減する |
| **最小限のテストデータセットを作成する** | データが少ない = リスクが少ない |
| **MCPサーバーのソースを監査する** | サードパーティMCPに脆弱性がある可能性がある |

### チーム向け

| 環境 | 推奨事項 |
|-------------|----------------|
| **開発** | オプトアウト + 除外 + 匿名化データ |
| **ステージング** | 実データを扱う場合はEnterprise APIを検討 |
| **本番** | Claude Codeを直接接続しない |


## 5. 他のツールとの比較

| 機能 | Claude Code + MCP | Cursor | GitHub Copilot |
|---------|-------------------|--------|----------------|
| 送信されるデータスコープ | 完全なSQLの結果、ファイル | コードスニペット | コードスニペット |
| 本番DBアクセス | あり（MCP経由） | 限定的 | 設計されていない |
| デフォルトの保持期間 | 5年 | 可変 | 30日 |
| デフォルトのトレーニング | あり | オプトイン | オプトイン |

**主な違い**: MCPはMCPサーバーが独立したネットワーク/ファイルシステムアクセスを持つ別プロセスであるため、独自の攻撃対象領域を生み出す。


## 6. エンタープライズの考慮事項

### Enterprise API（ZDR）を使用するタイミング

- PII（名前、メール、住所）を扱う場合
- 規制産業（HIPAA、GDPR、PCI-DSS）
- クライアントデータの処理
- 政府契約
- 金融サービス

### 評価チェックリスト

- [ ] 組織のデータ分類ポリシーが存在する

- [ ] 潜在的なデータ露出のインシデント対応計画がある
- [ ] 法務/コンプライアンスのレビューが完了している

## 8. 知的財産の考慮事項

> **免責事項**: これは法的アドバイスではない。あなたの具体的な状況については資格のある弁護士に相談すること。

AIコード生成ツールを使用する場合、法務チームとこれらの点について議論すること:

| 考慮事項 | 議論すべき内容 |
|---------------|-----------------|
| **所有権** | AI生成コードの著作権の状態はほとんどの法域で法的に未解決のまま |
| **ライセンス汚染** | トレーニングデータには、コードベースに影響を与える可能性のあるコピーレフトライセンス（GPL、AGPL）のオープンソースコードが含まれている可能性がある |
| **ベンダーの補償** | 一部のエンタープライズプランは法的保護を提供する（例: Microsoft Copilot EnterpriseにはIPの補償が含まれる） |
| **セクターコンプライアンス** | 規制産業（医療、金融、政府）には追加のIP要件がある可能性がある |

このガイドはClaude Codeの使用に焦点を当てており、法的戦略ではない。IPガイダンスについては、専門の法的リソースまたは組織の法務顧問に相談すること。


## 9. Claudeのガバナンスと価値観

### Constitutional AIフレームワーク

Anthropicは2026年1月にClaudeの構成（CC0ライセンス - パブリックドメイン）を公開した。この文書はClaudeの動作を導く価値階層を定義している:

**優先順位**（競合解決に使用）:

1. **広範に安全** — 人間の監督と制御を絶対に妥協しない
2. **広範に倫理的** — 誠実さ、危害の回避、適切な行動
3. **Anthropicコンプライアンス** — 内部ガイドラインとポリシー
4. **真に有用** — ユーザーと社会に対する本当の有用性

### Claude Codeユーザーにとっての意味

| シナリオ | 期待される動作 |
|----------|-------------------|
| セキュリティに敏感なリクエスト | Claudeは有用性よりも安全性を優先する（より保守的になる可能性がある） |
| 境界線上の生物学/化学 | 安全への影響を評価するためにコンテキストを求めて拒否するかもしれない |
| 倫理的な衝突 | 階層に従う: 安全性 > 倫理 > コンプライアンス > 有用性 |

### なぜこれが重要か

- **トレーニングデータソース**: 構成は合成トレーニング例の生成に使用される
- **動作仕様**: 意図した出力と偶発的な出力を説明するリファレンスドキュメント
- **監査とガバナンス**: コンプライアンスレビューのための法的/倫理的基盤を提供する
- **独自のエージェント**: CC0ライセンスにより、カスタムモデルへの再利用/適応が許可される
