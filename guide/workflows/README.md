## 開発ワークフロー

### [プラン駆動開発](./plan-driven.md)

実行前にプランモードを使って複雑なタスクを構造化します。

**使う場面**: 複数ステップの機能、アーキテクチャの変更、アプローチが不明確な場合

### [ClaudeによるTDD](./tdd-with-claude.md)

テスト駆動開発ワークフロー: まずテストを書き、その後に実装する。

**使う場面**: 重要な機能、リグレッション防止、API設計

### [仕様ファースト開発](./spec-first.md)

より良い要件の明確化のため、コードより先に仕様を書く。

**使う場面**: チームコラボレーション、複雑な機能、ドキュメントファーストのプロジェクト

### [イテレーティブ・リファインメント](./iterative-refinement.md)

複数のリファインメントサイクルを通じてコードを改善します。

**使う場面**: 品質改善、パフォーマンス最適化、コードのクリーンアップ

### [スケルトンプロジェクト](./skeleton-projects.md) ⭐ NEW

実績のある既存リポジトリを新規プロジェクトのスキャフォールドとして使います。

**使う場面**: 新規プロジェクトの開始、チームパターンの標準化、実証済みの基盤からの迅速なプロトタイピング

### [チームAIインストラクション管理](./team-ai-instructions.md)

プロファイルベースのモジュールアセンブリで、複数の開発者・複数ツールのチームにCLAUDE.mdをスケールさせます。

**使う場面**: 5人以上の開発者チーム、複数のAIツール（Claude Code + Cursor/Windsurf）、OS混在環境

### [Changelogフラグメント](./changelog-fragments.md) ⭐ NEW

**3層システムによるPRごとのドキュメント強制: CLAUDE.mdルール + UserPromptSubmitフック + CIゲート**

`CHANGELOG.md`のマージコンフリクトを排除し、実装時にコンテキストを記録し、DBマイグレーションがサイレントにデプロイされることを防ぎます。また、必須のワークフローステップを強制するための再利用可能な`UserPromptSubmit`フックパターンを含みます。

**主なトピック**:
- 自律的なフラグメント作成のためのCLAUDE.mdワークフロールール
- 3段階優先度（強制、発見、コンテキスト）を持つ`UserPromptSubmit`フック
- 条件付き提案パターン: 「PRの意図があるがフラグメントへの言及がない場合」
- 独立したマイグレーションチェックジョブによるCI強制

### [RPI: リサーチ → プラン → 実装](./rpi.md) ⭐ NEW

**フェーズ間に明示的な検証ゲートを持つ3フェーズの機能開発**

3つのロックされたフェーズで機能を構築します: まずフィジビリティをリサーチし、次に実装をプランし、最後にコードを書く。各フェーズは具体的な成果物を生成します（RESEARCH.md → PLAN.md → コード）。各ゲートは次のフェーズを開始する前に明示的なGOが必要です。

**使う場面**: フィジビリティが不明確な機能、1日以上の作業、未知の技術領域、または誤った仮定を遅くに発見するコストが高い場面

### [GitHub Actionsワークフロー](./github-actions.md) ⭐ NEW

**PRレビュー、イシューのトリアージ、品質ゲートを自動化する5つの本番対応パターン**

公式の`claude-code-action`を通じてClaudeをGitHubワークフローに直接接続します。2つのモード: インタラクティブ（`@claude`メンション）と完全自動化（push/スケジュールトリガー）。

**主なトピック**:
- `/install-github-app`によるセットアップ（30秒クイックスタート）
- パターン1: `@claude`メンションによるオンデマンドPRレビュー
- パターン2: すべてのpushで自動レビュー
- パターン3: イシューのトリアージとラベリング
- パターン4: 機密パスのセキュリティ重視レビュー
- パターン5: 週次スケジュールによるリポジトリヘルスチェック
- コスト制御、並行性、フォークの安全性

**使う場面**: インフラを管理せずにAIを活用したコードレビューを望むすべてのチーム

---

### [コグニティブモード切り替え](./gstack-workflow.md) ⭐ NEW

シップサイクル全体でスペシャリストの役割を切り替えます: 戦略的プロダクトゲート、アーキテクチャレビュー、慎重なコードレビュー、自動リリース、ネイティブブラウザQA、振り返り。

**使う場面**: プロダクト方向性、エンジニアリングの厳密さ、レビュー、リリースの間に明示的な分離が必要なシップサイクルで、汎用アシスタントがすべてのフェーズを担当するのではなく

## デザインとコンテンツ

### [デザインからコードへ](./design-to-code.md)

デザインモックアップ（Figma、ワイヤーフレーム）を動作するコードに変換します。

**使う場面**: フロントエンド開発、UI実装、デザインシステムの作業

### [OG画像生成](./og-image-generation.md)

Satoriとresvgでビルド時にソーシャルプレビュー画像を動的に生成します。

**使う場面**: Astroプロジェクト、静的PNGを管理せずにソーシャルプレビューを最新に保つ場合

### [PDF生成](./pdf-generation.md)

Claude CodeでQuarto/Typstを使ってプロフェッショナルなPDFを生成します。

**使う場面**: レポート、ドキュメント、ホワイトペーパー、技術文書

### [トーク準備パイプライン](./talk-pipeline.md) ⭐ NEW

6ステージのスキルパイプライン: 生素材 → 構造化されたトーク → Kimiによる AIスライド生成。

**使う場面**: カンファレンストーク、ミートアップ発表、社内技術トーク — 記事、トランスクリプト、メモから

### [TTSセットアップ](./tts-setup.md)

Claude Codeのレスポンスにテキスト読み上げを設定します（Agent Vibesインテグレーション）。

**使う場面**: 音声フィードバック、アクセシビリティ、ハンズフリーコーディング

## マルチエージェントと高度な機能

### [エージェントチーム](./agent-teams.md)

複雑なタスクに並行して取り組む複数の専門化されたエージェントをオーケストレーションします。

**使う場面**: 並列処理、専門的な知識、または独立した検証から恩恵を受けるタスク

### [エージェントチームクイックスタート](./agent-teams-quick-start.md)

30分以内に最初のエージェントチームをセットアップするための速習ガイド。

**使う場面**: マルチエージェントパターンが初めて、完全なセットアップに踏み込む前に試してみたい場合

### [デュアルインスタンスプランニング](./dual-instance-planning.md)

2つの連携したClaude Codeインスタンスで、プランニングにOpusを使い、実行にSonnetを使います。

**使う場面**: アーキテクチャに深い推論が必要な複雑な機能、コスト効率の高い実行

### [イベント駆動エージェント](./event-driven-agents.md)

直接のオーケストレーションではなく、フックイベントを通じてエージェントを調整します。

**使う場面**: リアクティブなワークフロー、フック起動の自動化、疎結合なエージェントパイプライン

### [プランパイプライン](./plan-pipeline.md)

エンドツーエンドのプランパイプライン: /plan-start、/plan-validate、/plan-executeを一貫したワークフローとして。

**使う場面**: コードを書く前にプランニングの厳密さが報われるあらゆる重要な機能

### [タスク管理](./task-management.md)

TodoWrite、Tasks API、セッション間のコンテキスト永続化によるマルチセッションのタスク追跡。

**使う場面**: 複数セッションにまたがる長期タスク、チーム連携、複雑なバックログ
