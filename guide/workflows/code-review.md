# コードレビュー

> **利用可能性**: リサーチプレビュー — TeamsおよびEnterpriseプランのみ。Free/Proアカウント、またはZero Data Retention（ZDR）が有効な組織では利用できません。
> **ローンチ**: 2026年3月9日

Claude CodeのCode Review機能は、すべてのGitHubプルリクエストに対してマルチエージェントレビューを実行します。専門化されたエージェントのフリートがコードベース全体のコンテキストの中でdiffを検査し、それぞれが異なるクラスの問題（ロジックエラー、セキュリティ脆弱性、エッジケース、リグレッション）を調べ、その後に偽陽性をフィルタリングする検証パスが続きます。

調査結果は問題が見つかった特定の行にインラインのPRコメントとして投稿され、重大度でタグ付けされます。レビューはPRを承認またはブロックしないため、既存のレビューワークフローはそのまま維持されます。

---

## 仕組み

1. トリガーが発火（PRのオープン、プッシュ、または手動の`@claude review`コメント）
2. 複数のエージェントがAnthropicのインフラ上でdiffと周辺コードを並行して分析
3. 各エージェントが異なるクラスの問題をターゲットにする
4. 検証ステップで候補を実際のコードの振る舞いに対して確認し、偽陽性を除去
5. 結果が重大度でランク付けされ、重複排除されて、インラインのPRコメントとして投稿
6. 問題が見つからない場合、Claudeは短い確認コメントを投稿

レビューはPRのサイズと複雑さに応じてスケールし、**平均20分で完了**します。

### 重大度レベル

| マーカー | 重大度 | 意味 |
|:-------|:---------|:--------|
| 🔴 | Normal | マージ前に修正すべきバグ |
| 🟡 | Nit | マイナーな問題、修正する価値はあるがブロッキングではない |
| 🟣 | Pre-existing | このPRで導入されたものではない、コードベース内の既存バグ |

各調査結果には、Claudeがその問題にフラグを立てた理由と問題を確認した方法を説明する折りたたみ可能な詳細推論セクションが含まれます。

## セットアップ

管理者が組織に対してCode Reviewを一度有効にし、含めるリポジトリを選択します。

### 1. 管理者設定を開く

[claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code)にアクセスし、**Code Review**セクションを見つけてください。Claude組織への管理者アクセスと、GitHub組織にGitHub Appsをインストールする権限の両方が必要です。

### 2. Setupをクリック

GitHub Appインストールフローが始まります。

### 3. Claude GitHub Appをインストール

プロンプトに従って、GitHub組織にClaude GitHub Appをインストールしてください。アプリは以下を要求します:

- **Contents**: 読み取りと書き込み
- **Issues**: 読み取りと書き込み
- **Pull requests**: 読み取りと書き込み

Code Reviewはコンテンツへの読み取りアクセスとプルリクエストへの書き込みアクセスを使用します。この権限セットは、後で有効にする場合は[GitHub Actions](/en/github-actions)もサポートします。

### 4. リポジトリを選択

有効にするリポジトリを選択してください。リポジトリが見つからない場合は、インストール時にGitHub Appへのアクセスを許可したか確認してください。後で管理者設定テーブルからリポジトリを追加できます。

### 5. リポジトリごとにレビュートリガーを設定

各リポジトリについて、レビューをいつ実行するかを選択してください:

| トリガー | 実行タイミング | コストプロファイル |
|---------|-------------|--------------|
| **PR作成後1回** | PRがオープンまたはready for reviewにマークされたとき1回 | 最低 |
| **すべてのプッシュ後** | PRブランチへのすべてのプッシュで | 最高（プッシュ数倍）|
| **手動** | 誰かが`@claude review`とコメントしたときのみ | 制御可能 |

`@claude review`コメントの後、そのPRへのその後のプッシュは設定されたトリガーに関わらず自動的にレビューをトリガーします。

**手動モード**は、特定のPRを選んでレビューに追加したい高トラフィックのリポジトリや、PRがレビューの準備ができたときだけレビューを開始したい場合に便利です。

## 手動トリガー

オープンされた非ドラフトPRに`@claude review`とコメントしてすぐにレビューを開始します。要件:

- トップレベルのPRコメント（インラインのdiffコメントではない）
- コメントの先頭に`@claude review`
- リポジトリへのオーナー、メンバー、またはコラボレーターアクセス

レビューがすでに実行中の場合、リクエストは進行中のレビューが完了するまでキューに入れられます。

---

## レビューの設定

2つのファイルがClaudeのフラグを立てる内容を制御します。どちらもデフォルトの正確さチェックに加えて使用されます。

### CLAUDE.md

Claudeはディレクトリ階層内のすべての`CLAUDE.md`ファイルを読み取ります。新たに導入された違反はnit レベルの調査結果としてフラグが立てられます。双方向: PRが`CLAUDE.md`の記述を時代遅れにする場合、Claudeはドキュメントの更新が必要だとフラグを立てます。

`CLAUDE.md`はインタラクティブなClaude Codeセッションにも適用されるガイダンスに使用してください。

### REVIEW.md

レビューのみのルールのために、**リポジトリルート**に`REVIEW.md`を追加してください。自動的に検出され、設定は不要です。

```markdown
# コードレビューガイドライン

## 常に確認する
- 新しいAPIエンドポイントには対応する統合テストがある
- データベースマイグレーションは後方互換性がある
- エラーメッセージはユーザーに内部詳細を漏洩しない

## スタイル
- ネストされた条件分岐より早期リターンを好む
- ログ呼び出しではf文字列補間ではなく構造化ロギングを使用する

## スキップ
- `src/gen/`以下の生成されたファイル
- `*.lock`ファイルのフォーマットのみの変更
- `db/migrations/`内のマイグレーションファイル
```

`CLAUDE.md`で一般セッションに対して煩雑になるルール（リンター規約、スキップリスト、チーム固有のパターン）に`REVIEW.md`を使用してください。

## 価格

Code Reviewはトークン使用量で請求されます。**プランの含まれる使用量とは別に**（[extra usage](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans)経由）。

- 平均コスト: **レビューあたり$15〜25**、PRサイズ、コードベースの複雑さ、検証が必要な問題の数に応じてスケール
- 「すべてのプッシュ後」はプッシュ数でコストが倍増する
- 月ごとの支出上限を設定するには: [claude.ai/admin-settings/usage](https://claude.ai/admin-settings/usage) → 「Claude Code Review」サービスの制限を設定
- 支出を監視: [claude.ai/analytics/code-review](https://claude.ai/analytics/code-review)（日次PRカウント、週次支出、リポジトリ別内訳）

## 既知の制限（リサーチプレビュー）

- TeamsとEnterpriseのみ — Free/Proアクセスなし
- Zero Data Retention（ZDR）が有効な組織では利用不可
- マネージドサービスとしてはGitHubのみ（GitLabはCI/CDインテグレーション経由でサポート、この機能ではない）
- 大規模なリポジトリの初回アクティベーション時のフルリポジトリインデックスの遅延
- Anthropicの内部統計: 1000行以上のPRで約7.5の問題を発見、偽陽性率<1% — 自己報告であり、独立した検証なし
